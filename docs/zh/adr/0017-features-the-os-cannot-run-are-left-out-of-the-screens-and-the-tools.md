# 该 OS 上无法使用的功能，不出现在界面里，也不出现在模型的工具里

main 在启动时只决定一次该 OS 和机器上可用的功能，renderer 和模型的工具只看这个值。要决定的是运行本地语音识别和 Qwen3-TTS 的 GPU、回声消除的原生麦克风、全局快捷键。无法使用的功能，选项、开关、卡片、工具都不出现。像本地语音识别这样用户有地方选择的功能，在那个地方给出无法使用的原因。本该可用的功能失败时，照旧作为错误显示。在 ASIST 不支持的 OS 与 CPU 组合上，不推测可用的功能，直接停止启动。如果先摆出来、用的时候才失败，例如没有独立 GPU 的 Windows 上首次设置时语音识别的准备会失败，用户要看到失败之后才能继续往下走。

在 ASIST 支持的任何一个 OS 上都能用的功能，不做成值。因为无论在哪里都是同一个值的判断，只会留下走不到的分支。在 CPU 上运行的 Python worker（记忆检索、附和分类器、MaAI）在 Windows 的 CPU 上也能跑，所以不做成值，任何 OS 上都出现。日历也一样，任何 OS 上都是通过 Google Calendar API 读取，所以不做成值。

## 未采纳的方案

- **把 OS 的名字传给 renderer，由每个界面自己判断。** 判断散落到每个界面，数量与界面数一样多，传给模型的工具列表和界面的显隐就会错位。

## 实测

2026-09-27，Windows 11，Core i9-9900K（8 线程），从用 `npm run dev` 启动的应用里，准备并运行了 3 个在 CPU 上运行的 worker。准备所需的时间，包含在约 1.5 MB/s 的线路上的下载，附和分类器 58 秒，记忆检索 59 秒，MaAI 171 秒。MaAI 的 worker 在 CPU 上启动，实时播放 12 秒的音频时，每个 80 ms 的帧的推理中位数为 59.8 ms，第 90 百分位为 63.8 ms，最大为 66.7 ms，都没有超过帧的长度。

## 已知限制

- 功能无法使用的原因，只出现在用户有地方选择的功能上。回声消除在该 OS 上只是从界面里消失而已。

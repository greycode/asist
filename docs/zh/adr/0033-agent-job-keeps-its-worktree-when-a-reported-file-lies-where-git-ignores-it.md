# 任务告知的文件位于 git 忽略的位置时，不询问用户、也不清理 worktree，交给用户处理

用 worktree 隔离的任务的提交里，不包含 Agent 写下的文件中被 git 忽略的那些（dist/ 或 .env 等）。合入只搬运提交，合入时和清理没有变更的任务时，worktree 都是整个文件夹一起消失。因此，Agent 把受托的成果物只写到被忽略的位置时，成果物就在完全没有询问用户的情况下消失了。ASIST 把 Agent 告知写过的文件（成果物）当中位于 worktree 内、没有进入提交的，计为不会合入的文件。后续的任务在前一个任务留下的 worktree 里运行，所以前一个任务以及再前一个任务告知的文件也计入。有这类文件的任务，即使没有其他变更也保留 worktree、进入待合入状态，由用户决定合入还是丢弃。在卡片的差异里、合入与丢弃的确认界面上、以及模型用 get_agent_job 读取的差异里，都作为不会合入、会随 worktree 一起消失的文件列出名字。没有其他变更、只因为有这类文件而留下来的任务，会记录该文件，在任务的报告里也告知这个名字，建议不要合入，而是把文件移走之后再丢弃。为了让用户能打开文件并移动，从卡片和 show_files 都能读取整个任务的 worktree。合入之后，把它们从成果物列表中移除。记忆的整理任务不向用户展示 worktree，所以不做这种处理，照旧清理。

## 未采纳的方案

- **只要 worktree 里有被忽略的新文件，不管有没有告知都保留。** 安装了依赖或做过构建的任务（node_modules、dist、.next、__pycache__ 等）都会留在待合入状态。git 无法合入这些内容，用户只能丢弃。
- **在合入时把不会合入的文件复制到合入目标。** 这等于把不出现在合入确认界面差异里的文件写进用户的工作树，可能覆盖用户在同一位置已有的文件（.env 等）。
- **只在清理之前告知。** 对于没有变更的任务，等到告知时 worktree 已经消失，用户取不出文件。

## 已知限制

- Agent 没有作为成果物告知的文件（例如用 shell 重定向写出的）不计入，所以若位于被忽略的位置，就会随没有变更的任务的 worktree 一起消失。
- 任务里只有不会合入的文件时，就没有可合入的变更，合入会被拒绝。打开需要的文件，移到别处之后，再丢弃任务。

# 每轮变化的信息不放进系统提示词，只在变化时附在输入上

像运行中的任务已经过了几分钟这样每轮都会变的信息，不放进系统提示词。当时的状况附在用户的发言或应用发来的通知上，并以相同的形式存进对话日志。只在它与历史里保留的最后一次状况不同时才附加。这是因为任何提供商都会把消息缓存在系统提示词的后面，系统提示词只要有一点点变化，它后面的整段历史每轮都要重读、重写。任务的状况在任务运行期间和结束后的 30 分钟里每分钟都在变，放进系统提示词的话，若历史有 10 万 token，这期间的每一轮都要整个重发。附在发言上保存，下一轮就会以相同的形式送出，被缓存的部分就不会变。只在变化时附加，是为了不让不变的项目列表每轮都堆进历史。状况变空时，只把已经变空这件事告诉模型一次，免得模型把最后一次看到的状况继续当成现在的状况读下去。

在 Gemini Live 里，任务的状况附在每次打开会话时发送的时间通知上。这是因为重新开始的会话会一直保留它第一次打开时的指令文本，放进指令文本的状况就一直是旧的。这里也只在该会话最后读到的状况不同时附加。这条通知不存进对话日志。之后打开的会话拿到的历史里也不放记忆的注记和任务的状况，因为每个会话都从自己打开时的通知读取当前的时间和状况，存了也没有可读的地方。

## 未采纳的方案

- **放在系统提示词的最后，并且后面不放缓存的断点。** 即使不放断点，消息的缓存也在系统提示词的后面，所以每轮都会落在缓存之外。为这种放法而存在的“每轮变化的层”机制已经删掉，免得同样的错误再回来。

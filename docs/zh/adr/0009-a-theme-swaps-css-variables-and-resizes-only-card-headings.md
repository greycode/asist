# 主题用一组 CSS 变量的值表示，只允许卡片标题改变大小

界面的外观——颜色、面、线、圆角、光晕、背景图、卡片标题的字体——都从按角色命名的 CSS 变量读取。组件不直接写颜色。主题就是这些变量的一组值，除 future 以外的主题要给除标题字体之外的所有变量写上自己的值。漏写的值会保持 future 的值，因为即使明亮主题里只留下 1 处深色，也不会有人发现。每张卡片只带 1 个色调，边框、背景、阴影、强调色都由主题从这个色调生成。主题可以改变的大小，只有卡片标题（标签、标题、大数字）的字体、字号和对齐方式；正文的字号和留白在任何主题下都相同。卡片的 s / m / l 切换依赖实测的高度，把可改的范围收窄到标题，是因为即使截断检查随主题数量增加，也还追得过来。由于标题会改变高度，截断检查要在所有主题与所有语言的组合下做。天气和时钟卡片的图在任何主题下都保持夜晚的景色，其上的文字用 future 的颜色写。

## 未采纳的方案

- **按主题改变卡片的布局（排列方式）。** 卡片内部的排列由各卡片的 JSX 决定，就要按主题拆分 JSX，s / m / l 的高度也要按主题重新测量。
- **界面的截断只用 future 测，只有卡片按主题逐个测。** CI 只会多花几秒，但以后主题开始改变界面的字体或留白时，检查就会漏掉。
- **按主题重画天气的风景。** 每个都道府县各有一张，共 48 张，都是用黄昏的光画的。为了白天外观的主题，就要把所有图重做一遍。

## 实测

- 截断检查（`npm run demo:fit`）在 1 个主题下约 20 秒，在 4 个主题下约 31 秒（10 核的 Mac，2026-09-24）。主题切换不重新加载页面，所以耗时并不与主题数量成正比。

## 已知限制

- 中央的球体、Dock 的图标、球体周围用 canvas 画的光点，在任何主题下都保持 future 的外观。要改变它们，需要按主题准备图和颜色。

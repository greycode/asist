# 记忆连标题在内都用对话的语言写，模板在对话的 11 种语言里都有，整理的指令只有日语和英语

记忆（me.md、user.md、页面、日记）连 ASIST 按名字读取的标题在内，都用对话的语言写。整理的 Agent 使用的模板（me.md、user.md、页面、日记）在对话的 11 种语言里都有，ASIST 把当天对话语言的模板放进技能。Agent 从模板取来的标题要一字一句照抄。页面开头的摘要和最后的印象、日记最后的标题，无论是哪种语言的形式，ASIST 都按名字读取；模板写出的标题，无论哪种语言，都不作为检索的词。改变对话语言之前写的页面，也照样能读。这是因为 Agent 自己翻译标题的话，每次整理都会出现不同的说法，就分不清哪个是模板的标题、哪个是 Agent 配合内容选出的标题。

写整理步骤的技能正文只留日语和英语两种。日语的对话用日语正文，其余 10 种语言用英语正文，英语正文以英语模板的形式点名模板的标题，并说明其他语言的模板在同一位置用该语言写着相同的标题。用英语正文和各语言的模板，Agent 照抄标题，并用该语言写正文（实测）。翻译正文不会让照抄变得更好，只是每次改步骤时，把 11 份正文凑齐的麻烦多出来而已。

## 未采纳的方案

- **固定的标题在日语记忆里用日语，在其他语言的记忆里用英语。** 不需要按语言列标题的表，但在其他语言的记忆里正文和标题的语言不一致，me.md 示例的标题会被 Agent 翻译，每次整理都会变来变去。
- **技能的正文也备 11 种语言。** 如上所述，照抄的方式并没有变。

## 实测

2026-10-03，用 Gemini 3.8 Flash（温度 1.0）代替整理的 Agent 做了测量。把德语、印地语、韩语各一天的对话（和新上司一起吃午饭的事、在常去的店里的点法、希望早上回答简短一点的请求、晚上盆景的话题）交给一份没有页面、也没有日记的记忆去整理。不让它执行命令，只给出技能的正文和该语言的模板，让它输出写好的文件，之后再交给 validate.py 跑。用英语正文对每种语言跑 5 次，用同一份正文经 Gemini 译成该语言后的文本（模板的标题按该语言的形式点名）也各跑 5 次。

| | 英语正文 | 译出的正文 |
|---|---|---|
| 页面开头和最后的标题与模板一致 | 29 张中 29 | 26 张中 26 |
| 日记最后的标题与模板一致 | 15 天中 15 | 15 天中 15 |
| user.md 的标题与模板一致 | 60 中 60 | 60 中 60 |
| me.md 的标题与模板的示例之一相同 | 92 中 92 | 92 中 92 |
| 英语标题 | 0 | 0 |
| validate.py 通过 | 15 次中 15 | 15 次中 15 |

两种做法下，正文都是用该语言写的。

## 已知限制

- 写在第一个标题之前的句子，若该文档里有任一语言的摘要标题，就作为该标题下的句子来读。没有的话，在靠假名能认出的日语、靠谚文能认出的韩语、靠天城文能认出的印地语里，作为该语言摘要标题下的句子读；在用拉丁字母书写的 8 种语言里，作为英语的“Summary”标题下的句子读。拉丁字母的语言之间无法从文字上分辨。没有摘要标题的页面，要提示补上对话语言的摘要标题。
- ASIST 按名字读取的标题（页面的开头和最后、日记的最后），在产出之后改动了说法，就会读不出以往记忆里留下的标题。其他模板的标题也一样，一旦改动，以往记忆里留下的标题就又会变回检索用的词。
- 日语和英语以外的模板文本，没有经过母语者阅读确认。

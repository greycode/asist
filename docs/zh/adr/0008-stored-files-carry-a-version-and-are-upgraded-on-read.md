# 保存的 JSON 文件带有格式版本，读取时迁移到当前版本

保存在 userData 里的 JSON 文件（设置、任务、定时器、Agent 任务、记忆的整理状态、API 的使用量、项目列表、邮件草稿、加密后的密钥和密码），在开头的 `version` 里写明格式版本。没有 `version` 的文件是写版本之前的格式，按版本 1 处理。改变格式时，哪怕只增加 1 个字段也要提升版本，并增加一个从前一个版本迁移过来的函数。迁移函数不删除，而是逐层累积。读取时若是旧版本，先把原文件保留为 `<名称>.v<版本>.json`，再依次迁移并重写。如果版本比应用已知的版本更新，就直接停下，不读取。因为分发出去之后，每改变一次格式，用户的应用就会无法启动，用户只能手动修改文件。旧应用读取新版本的文件时，有可能丢掉不认识的字段再写回去。

## 未采纳的方案

- **格式改变后丢弃旧文件。** 开发期间按这个方针做，所以不必有迁移函数。分发之后，用户的设置和任务会丢失。
- **只增加字段的变更不提升版本。** 新应用能用默认值读取，但旧应用会因为不认识的字段而拒绝新文件，无法与损坏的文件区分。

## 已知限制

- 记忆和笔记的 Markdown 不迁移。因为这是用户手动修改的文档，改变格式规则时，让整理 Agent 重写。
- 对话日志和 Agent 任务的日志（JSONL）、邮件缓存和记忆的索引（SQLite）不在这套机制之内。

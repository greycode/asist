# Excel 的工作表按 XML 原样保留，只解析要显示的行

Excel 查看器在预览的 iframe 里，把所选工作表的 XML 以解压开的字节序列原样保留，并为每行的起始位置只建一次索引。卡片或放大显示要取行时，只把那一行的字节转成字符串来解析，再从共享字符串和格式生成要显示的文字。共享字符串也同样以字节序列和索引保留，只解析用到的字符串。放大显示会给出所有行，但只绘制可见范围和前后各 1 屏的行，离开视线的行则释放掉。用 SheetJS 读入的工作表会为每个单元格建对象，同一个工作表也要多用一倍左右的内存，到第一行出现为止的时间也长，所以读取工作表时不用它。只有把数值和日期按显示格式转成文字这一部分，才使用 SheetJS 的格式部分（SSF）。

## 未采纳的方案

- **用 SheetJS 只读入选中的工作表，并保留其结果。** 取出行的代码会更短，但如下面的实测所示，内存和到第一行出现为止的时间都更多。

## 实测

2026-10-02，Apple M5（内存 32 GB），在 headless Chrome 里打开的 demo（`npm run demo:viewer-budgets` 的 2 个文件）。iframe 占用的内存，是在打开文件后做一次垃圾回收，再测量与打开小工作簿时的差值。

- 5 万行的工作表（XML 19 MB），这种方式下是 21 MB，SheetJS 的 dense 格式下是 40 MB。含 5 张 4 万行工作表的工作簿（共享字符串 20 万个）是 22 MB 和 58 MB。
- 到卡片上出现第一行为止的时间，这种方式是 173～175 ms，SheetJS 是 686～869 ms（负载平均 20 左右）。

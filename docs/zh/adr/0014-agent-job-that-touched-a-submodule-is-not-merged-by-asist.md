# 碰到子模块的 Agent 任务，ASIST 不合入，保留 worktree 交给用户

汇总在 worktree 中隔离的任务改动的提交，会把 Agent 留在 worktree 里的东西原样提交，既不重写子模块的条目，也不重写 .gitmodules。合入会给用户分支带来的改动，也就是从与用户当前 HEAD 的合流点（merge base）到任务提交的差异，如果碰到了子模块，ASIST 就不合入这个任务。碰到是指存在下列任何一种情况：子模块所指提交的改变、.gitmodules 的改变、子模块的添加或删除、普通文件夹与子模块的互换。Agent 改变了子模块自身的工作文件夹里的东西时（在其中提交、编辑或添加文件、向尚未初始化的文件夹写入），也做同样处理。在 worktree 中初始化的子模块仓库位于 worktree 的 git 文件夹里，会随 worktree 一起消失。那个提交是否在别处也存在，本地确认不了，所以子模块的文件夹里有东西时（包括它自己的 .git），以及 worktree 的 git 文件夹里还留着该子模块的仓库时（deinit 之后也会留下），都当作里面可能有工作来处理。子模块从 index 的条目里找，而不是从 .gitmodules 里找。因为也有不列在 .gitmodules 里的仓库。不问就清理 worktree，只在差异里和子模块里都没有可能丢失的东西时才做。ASIST 在清理任务、展示差异、为合入而读取的差异和状态，不能受仓库显示设置的左右，必须是准确的改动。`submodule.<name>.ignore` 和 `diff.ignoreSubmodules` 会从 git diff 和 git status 里都把子模块的改动藏起来，`status.showUntrackedFiles=no` 会藏起新文件，`diff.external` 和 textconv 会把 git diff 的输出换成别的东西。能覆盖这些设置的，只有命令的参数，所以 ASIST 在任何调用里都用参数覆盖后再读。

这类任务保留 worktree，放在等待合入的状态，并在卡片、合入确认界面、任务报告、get_agent_job 里说明：因为碰到了子模块，ASIST 无法合入，用户可以自己合入分支，或者丢弃。在子模块里做出的提交有时只存在于 worktree 里的副本中，这时即使用户的检出执行 git submodule update 也取不回来，所以还要说明必须先从这个 worktree 推送。丢弃会连那个副本一起消失，所以不只是从对话里，在卡片的“丢弃”里也一样，丢弃的那一刻如果 worktree 里可能有子模块的工作，就显示确认界面。合入按钮和 merge_agent_job 在显示确认界面之前就拒绝。Agent 在子模块里做出的提交有时只存在于 worktree 里的副本中，如果合入指向那个提交的条目，用户的仓库就会指向一个不存在的提交。另外，合入前展示的差异里只出现“Subproject commit”这一行，看不到里面变了什么。因此，ASIST 能确认的只到“是否碰到了子模块”为止，是否合入由能看到内容的用户决定。

## 未采纳的方案

- **只把子模块的条目和 .gitmodules 恢复到任务开始时或合流点的值再提交，其余改动照常合入。** 在提交里重写条目这件事本身就很危险。Agent 合入或 rebase 了用户的 main 或别的分支时，合入会把用户自己推进过的子模块退回原状，而展示的差异里也不会显示这一点。恢复到哪个值，取决于清理时打开的是哪个分支。子模块的 `ignore` 设置会藏起里面的改动，不问一声就删掉只存在于 worktree 里的工作。对于把路径换成子模块的改动，恢复之后的文件会以未提交的状态留下，任务就无法合入。
- **把子模块里的改动移到子模块的仓库里再合入。** 合入确认界面展示的差异里不出现子模块里的改动，等于把用户没看到的改动写进用户的另一个仓库。
- **把只有子模块里面变了的任务当作没有改动的任务，连 worktree 一起清掉。** 等于不问用户就删掉 Agent 提交的唯一副本。
- **只有当子模块的仓库里存在从 remote 的跟踪分支追溯不到的提交时，才把它算作工作。** 从 remote 来的提交也会被算作工作。只有 tag 指向的提交、浅 clone、在上游被删掉的分支、force push 之前的尖端都会这样。deinit 之后的仓库会漏掉。20 万提交的 clone 一次要花约 445 ms，每次清理和合入都会把主进程卡住。

## 已知限制

- 在任务里把子模块所指的提交更新到新的（把依赖升到最新）的改动，ASIST 无法合入。用户自己合入分支。
- Agent 只是为了构建而初始化了子模块的任务，ASIST 也无法合入。
- 版本 3 的历史中等待合入的任务，清理时没有做这项确认，所以在读取时会重新清理。

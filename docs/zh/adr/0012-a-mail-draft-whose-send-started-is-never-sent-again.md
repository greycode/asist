# 已经开始发送的邮件草稿，不会再发第二次

发送草稿时，在交给 SMTP 之前，先把开始发送的时刻写进草稿文件。这个时刻只在发送失败时删除，凡是时刻还留在文件里的草稿，一律不发送。发送之后删除草稿，可能因为磁盘异常等原因失败，此时草稿若仍处于可发送的状态，同一封邮件就会再一次送到真实存在的收件人手上。发送之后才写下的记录，会和删除一样因为同样的原因失败，所以能拦住第二次发送的，只有发送之前写下的记录。写不下发送之前的记录，就不发送。

## 未采纳的方案

- **把已发送的草稿记在内存里。** 重启应用就忘了，留在文件里的草稿又能发送。
- **发送前删掉草稿，失败后再恢复。** 删掉的那一刻草稿卡片就关闭，失败的原因没有地方显示。恢复用的写入失败时，正文也会丢失。

## 已知限制

- 发送途中应用退出时，无论是否发出，这封草稿都不能再发送。用户需要确认已发送文件夹，如果没有送到，就把正文复制到新邮件里发送。
- 发送失败之后没能删掉时刻时，这封草稿也不能发送。这一点会出现在错误信息里。
- 在不知道是否发出的失败中删除时刻。用户确认已发送文件夹之后，就能重新发送同一封草稿。

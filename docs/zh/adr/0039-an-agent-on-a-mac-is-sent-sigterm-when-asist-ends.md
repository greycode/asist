# 在 Mac 上，ASIST 退出时向正在运行的 Agent 发送 SIGTERM

Mac 上 Agent 的 CLI 在 ASIST 启动的进程组里运行。ASIST 每次启动 CLI 时，都在另一个会话里启动一个监视 shell。监视 shell 读取只有 ASIST 会写入的管道并等待。CLI 结束后 ASIST 往该管道写一行，监视 shell 什么也不做就退出。那一行始终没来、管道就关闭了的时候，也就是 ASIST 崩溃或被强制结束的时候，监视 shell 会向 CLI 的进程组以及当时能从 CLI 追溯到的子孙进程发送 SIGTERM。没有监视 shell 时，即使已经没有读取其输出的对象，CLI 也会继续工作，这期间无法从界面停下，也不留下日志。在 Windows 上由 launcher 在 ASIST 退出时停掉 Job。

无法启动监视 shell 时，例如进程数达到上限时，不启动 CLI，让任务失败。监视 shell 的用意，就是不去运行 ASIST 崩溃后也停不下来的 Agent；任务错误里会给出这一原因，用户之后可以重新开始。

## 未采纳的方案

- **交给下次启动时的回收处理。** 在作业结束之前，或者用户重新启动 ASIST 之前，无人看管的 Agent 会继续写，这期间的日志不会留下。
- **把监视 shell 放在 CLI 的进程组里，用 `kill -TERM 0` 发给整个组。** CLI 自己结束后监视 shell 仍留在组里，所以 ASIST 每次都会开始停止流程，连 CLI 留在组里的进程的工作也会中途停掉。即使监视 shell 用一行告知 CLI 已结束，ASIST 也多次在监视 shell 消失之前就查看了进程组。另外，环境里的 `SHELLOPTS` 含有 `monitor` 时，`/bin/sh`（bash）会把监视 shell 放进另一个组，信号只能到达监视 shell。
- **只发给 CLI 的进程组。** codex 把自己的命令放在别的进程组里运行，即使自己因 SIGTERM 结束，正在运行的命令也会原样一直跑到最后。
- **让监视 shell 按固定间隔查看 ASIST 的 PID。** 要到下一次查看时才会发现 ASIST 已经结束，这期间 Agent 会继续作业。用管道的话，ASIST 一结束就能立刻知道。
- **与 Windows 一样，Mac 也做一个启动用程序。** Mac 没有 Job Object，所以能做到的也只有监视 shell 那些事，只是多 1 个要签名的可执行文件。
- **监视 shell 在 SIGTERM 之后隔一段时间再发 SIGKILL。** claude 和 codex 收到 SIGTERM 后都在 1 秒多之内结束，所以不给监视 shell 加等待机制。
- **即使监视 shell 启动不了也启动 CLI，并在任务日志和卡片上说明这一点。** 这就会变成去运行一个 ASIST 崩溃后也停不下来的 Agent，为此卡片上还需要相应的显示。重新开始就能解决，所以不这样做。

## 实测

以下内容均在 2026-10-02 用 Apple M5 的 macOS 26.2 确认。

- 把代替 ASIST 启动 CLI 的进程强制结束时，claude 2.1.276 在没有监视 shell 的情况下先结束正在执行的命令，再向模型询问一次，还执行了下一条命令，然后在强制结束约 28 秒后才结束。有监视 shell 时，在强制结束约 1.1 秒后确认时它已经结束，正在执行的命令也没有跑到最后。
- 同样强制结束时，codex 0.155.0 在只向 CLI 的进程组发送 SIGTERM 时 0.1 秒内结束，但在别的组里运行的命令在强制结束 19 秒后跑到了最后。也发给子孙进程时，那条命令也没跑到最后。
- 用 `/bin/echo` 作为 CLI 让它自行结束时，把监视 shell 放在 CLI 的进程组里，20 次全部都是 ASIST 开始停止流程，到判定结束为止的时间中位数从 252 ms 延长到 491 ms。即使监视 shell 用一行告知已经结束，在关闭管道后立即查看时 40 次中有 39 次、在等待监视 shell 关闭管道时 40 次中有 3 次，ASIST 查看时监视 shell 仍留在组里。

## 已知限制

- 监视 shell 只发送 SIGTERM。不因 SIGTERM 结束的 CLI 和子孙进程，会一直运行到下次启动 ASIST 时回收为止。
- 监视 shell 发送 SIGTERM 的对象，只有 CLI 的组和当时能从 CLI 追溯到的子孙进程。父进程先结束、从 CLI 已无法追溯的进程收不到。下次启动时的回收会用 token 查找这类进程，但 Apple 提供的 shell 和命令不把环境暴露给 `ps`，所以用 token 找不到。
- CLI 结束后，ASIST 正在停掉组里残留进程的期间如果 ASIST 崩溃，监视 shell 已经结束，残留的进程就只能交给下次启动时回收。

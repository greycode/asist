# Agent 把 worktree 切到其他分支的任务，ASIST 不合入，而是告知该分支的名字，交给用户处理

任务的 worktree 开始时打开的是 ASIST 创建的任务分支。任务结束时，ASIST 把剩余的改动提交到该分支，合入的差异从该分支计算。Agent 被要求“ブランチを切ってコミットして”时，有时会在 worktree 中切到自己的分支，或者用 git branch -m 改掉任务分支的名字再提交。任务结束时如果 worktree 的 HEAD 没有指向任务分支，ASIST 不提交任何东西，把 worktree 原样留下并置为等待合入，记录 Agent 打开的分支的名字（改过名字时是新名字）。HEAD 是 detached 时，记录该提交。这样的任务 ASIST 不合入。在卡片、任务的报告、get_agent_job，以及被要求合入时给出的拒绝理由中，告知 ASIST 无法合入、该分支的名字，以及用户可以自行合入或丢弃。每次读取差异时也确认 worktree 的 HEAD，如果没有指向任务分支，就以同样的理由拒绝。

## 未采纳的方案

- **让 ASIST 的合入能合入 Agent 分支的提交。** 要求开分支的用户往往是想要分支本身，而不是合入。另外，Agent 打开的分支有时就是用户自己的分支，ASIST 在那里添加提交或从那里合入，会让用户的分支发生未被要求的变化。

## 已知限制

- 丢弃后，worktree 以及只存在于那里的改动（未提交的改动、在 detached HEAD 上做的提交）会消失。Agent 的分支及其提交留在用户的仓库里。任务分支被改名而已经不存在时，就原样保留，丢弃也就到此结束。
- 后续任务在同一个 worktree 中运行。结束时如果仍打开着别的分支，同样不合入。

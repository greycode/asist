# 本地的语音模型只在麦克风需要它的期间加载

语音识别（Qwen3-ASR）、MaAI 与附和种类的判定，只在声音引擎的麦克风打开期间运行，关掉麦克风就立刻停止。朗读的 Irodori-TTS 与 Qwen3-TTS 在打开麦克风时以及朗读某个内容时加载；麦克风关着时，从关掉麦克风起、或从最后一次加载或朗读起过了 5 分钟就停止。只是启动应用并不会加载，用 Gemini Live 说话时也不加载。打开麦克风后录音立即开始，第一次转写则等 worker 准备好。如果把模型一直放着，在不说话的时候也会持续占用内存：在语音识别还用 llama-server 运行的 2026-10-05，Apple M5 上持续用约 5 GB 内存，RTX 2080 上持续用 8 GB 中的 3.5～4 GB VRAM。迁移到 speech.cpp 之后，仅语音识别一项，Apple M5 上就用 1.1～2.5 GB 内存，RTX 2080 上用 0.9～2.7 GB VRAM（ADR 0059）。另一方面，重新加载如下面的实测所示是 1～3 秒，在打开麦克风后第一次说话的期间就能完成。只给朗读留 5 分钟的宽限，是因为关着麦克风用文字交谈时以及任务的报告也会用到朗读；如果每次回话都重新加载，每次声音都会延迟。

## 未采纳的方案

- **启动时加载，一直放到退出应用。** 在不说话的时候也持续占用上面说的内存与 VRAM。
- **保持麦克风打开，5 分钟没有对话就释放，VAD 捕捉到开口时再重新加载。** 重新加载 1～3 秒就能完成，所以配合麦克风去加载的规则更简单。但麦克风一直开着的话，每次有通过 VAD 的房间人声或电视声音，都要重新加载。
- **关着麦克风时，朗读也在每次说完回话后停止。** 如果用文字连续交谈，每次回话都要重新加载 2 秒左右（文件被从 OS 缓存中挤出去的话，Windows 上要 5 秒左右），其中无法在等待语言模型回话的这段时间里完成的部分，声音就会延迟。

## 实测

2026-10-05，从启动随应用打包的 speech.cpp worker 起，到可以使用为止的时间。在文件位于 OS 缓存中的状态下测量，括号内是从磁盘读取的第 1 次。Qwen3-ASR 是 2026-10-07 用 speech.cpp 0.7.1 的 worker 重新测的值。RTX 2080 上是从打开麦克风到 worker 报告准备完成为止的时间，VRAM 是 `nvidia-smi` 的 GPU 整体使用量中超出关着麦克风时的 1.64 GB 的部分。

| | Apple M5（32 GB）、Metal | RTX 2080（8 GB）、Vulkan |
|---|---|---|
| Qwen3-ASR | 1.7B 为 0.56～0.67 秒、0.6B 为 0.37～0.42 秒 | 1.7B 为 1.6 秒（5.7 秒）、VRAM 2.27 GB。0.6B 为 1.0 秒（2.5 秒）、VRAM 0.93 GB |
| Qwen3-TTS 0.6B | 2.2～2.5 秒 | 2.1 秒（4.7 秒）、VRAM 1.4 GB |
| Qwen3-TTS 1.7B | 3.1～3.3 秒 | 没有测过 |
| Irodori-TTS | 1.9～2.1 秒 | 1.7 秒（5.3 秒）、VRAM 2.1 GB |

## 已知限制

- 因 GPU 驱动程序故障等原因而无法启动模型，这一点要到打开麦克风时才会第一次知道，而不是在启动应用时。
- 装入新版本的应用或 GPU 驱动程序后的首次加载要生成 GPU 程序，需要 12～16 秒，那一次的首次转写就要等这么久。
- VOICEVOX 与 AivisSpeech 的引擎不会按朗读的句子逐个启动，所以这条规则不会停止它们。
